# セキュリティレビュー報告

対象: Moribito（Chrome拡張 / Manifest V3）
実施日: 2026-09-20
対象コミット: 初回コミット時点（拡張本体 約4,100行）

## 1. 参照した基準

| 基準 | 使い方 |
|---|---|
| **OWASP ASVS v4.0.3** | 観点の抽出元。各指摘に章番号を対応させた |
| **OWASP Top 10 (2021)** | A01 アクセス制御 / A03 インジェクション / A05 設定ミス / A10 SSRF |
| **Chrome Extension security guidance (MV3)** | 権限の最小化、リモートコード禁止、CSP、メッセージの信頼境界 |
| **UTS #39 / RFC 3492** | 表示偽装（ホモグリフ・BiDi）の扱い。本製品の検出対象でもあり、自身の表示にも適用が必要 |

ASVS のうち、本製品に該当しない章（認証・セッション管理・サーバー側アクセス制御など）は対象外とした。
拡張はサーバーを持たず、アカウントも扱わない。

## 2. 脅威モデル

信頼境界は3つある。

```
 ┌──────────────────────────────────────────────┐
 │ 拡張の内部（service worker / offscreen / 拡張ページ） │  ← 信頼する
 └──────────────────────────────────────────────┘
        ▲ ①               ▲ ②                ▲ ③
   利用者の操作        閲覧中のページのDOM      外部から取得したデータ
   （設定画面）        （攻撃者が完全に制御）    （リスト・評価API応答）
```

| # | 入力源 | 想定する攻撃者 | 主な脅威 |
|---|---|---|---|
| ① | 設定画面からの値 | 拡張のバグ、または利用者の誤設定 | 判定の無効化、意図しない外部通信 |
| ② | ページのDOM・タイトル・フォーム | **フィッシング犯（完全に制御可能）** | 警告表示の偽装、検出回避、拡張のクラッシュ |
| ③ | リスト成果物、リピュテーションAPI応答 | 取得元の侵害、中間者 | 不正なデータ投入、内部ネットワークへの誘導 |

**最重要は②**。フィッシング対策ツールが、フィッシング犯の作ったデータをそのまま画面に出す構造になっていないかを重点的に見た。

### 指摘1（High）: 警告画面の表示をページ側から偽装できた

**内容**
フォームの送信先ホスト名（ページが自由に決められる値）を、BiDi制御文字を含んだまま警告文に埋め込んでいた。

```js
// 修正前
detail: `送信先: ${form.actionHost}（表示中のドメインは ${pageRegistrable}）`
```

**なぜ問題か**
`action="https://collector‮evil‬.test/"` のような値を置かれると、
**警告画面の文字列そのものが反転して表示される**。フィッシングを警告するツールが、
その警告文の中で表示偽装を許していた。文字列としてはtextContentで挿入しているのでXSSにはならないが、
利用者が読む内容を攻撃者が操作できる時点で警告の意味が失われる。

**修正**
`sanitizeForDisplay()` を追加し、BiDi制御文字・ゼロ幅文字・C0/C1制御文字を除去して長さを打ち切る。
ページ由来の文字列を表示に使う箇所すべてに適用した。

**検証** `tests/unit/security.test.mjs` の V5.3 の2件

---

### 指摘2（High）: 任意のドメインを許可リストに登録させられる余地

**内容**
警告画面の「危険を承知で続行」が、対象ホスト名とURLをメッセージに載せて送り、
service worker はそれをそのまま許可リストへ書き込んでいた。

```js
// 修正前
case 'proceed': {
  const { host, permanent, url } = message;   // ← 送信側の申告を信用
```

**なぜ問題か**
警告画面は拡張自身のページなので直接の攻撃経路ではないが、
**「送信側の申告を信用して恒久的な許可を与える」構造そのものが誤り**（ASVS V1.4.1）。
警告画面にバグが1つ入るだけで、任意ドメインの恒久許可につながる。

**修正**
メッセージは `token` だけを受け取り、service worker が**ブロック時に自分で保存したレコード**から
ホスト名とURLを決める。未知のトークンは拒否する。

**検証** `tests/e2e/privacy.spec.mjs`「偽のトークンでは許可リストに追加できない」

---

### 指摘3（Medium）: 外部問い合わせ先が未検証

**内容**
リスト更新URL、リピュテーションAPI、DoHリゾルバのいずれも、スキームもホストも検証していなかった。

**なぜ問題か**
- `http://` を指定できる＝**中間者がリストを差し替えられる**（判定の無効化や誤ブロックの誘発）
- `https://127.0.0.1/` や `https://169.254.169.254/` を指定できる＝
  **利用者の内部ネットワークや、クラウドのメタデータエンドポイントへの踏み台**になりうる（SSRF相当）

**修正**
`assertSafeEndpoint()` を追加。https のみ、URL内の認証情報を禁止、
ループバック・RFC1918・リンクローカル・`.local`・IPv6 ULA を拒否。
**保存時と実行時の両方**で検証する。無効な場合は通信自体を行わない。

**検証** `tests/unit/security.test.mjs` の V9.1 / V5.5 の4件

---

### 指摘4（Medium）: 設定値が未検証

**内容**
`set-settings` が受け取った値をそのまま `chrome.storage.sync` に書いていた。
しきい値の範囲チェックは設定画面のUI側にしかなかった。

**なぜ問題か**
`blockThreshold: 0` が保存されると全ページがブロックされ、
`0.99` では何も検出しなくなる。許可リストに任意の文字列を入れられる。
**UIを唯一の検証点にしてはいけない**（ASVS V5.1.3）。

**修正**
`sanitizeSettingsPatch()` を追加し、保存前に必ず通す。
しきい値のクランプ、許可リストのホスト名形式検証と件数上限（500）、
既知キー以外の破棄、検出器/プロバイダIDの照合を行う。

**検証** `tests/unit/security.test.mjs` の V5.1 の4件

---

### 指摘5（Medium）: CSP が未指定

**内容** `manifest.json` に `content_security_policy` を書いていなかった。

**なぜ問題か**
MV3 の既定 CSP でもリモートスクリプトは防げるが、
`base-uri` と `form-action` は制限されない。拡張ページに万一インジェクションが入った場合の
被害範囲が広がる。多層防御として明示すべき（ASVS V14.4.3）。

**修正**
```json
"content_security_policy": {
  "extension_pages": "script-src 'self'; object-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'"
}
```

### 指摘10（Info）: 自然言語の文字列マッチ判定を撤去

セキュリティ実装の不備ではないが、**誤検知は警告の価値を毀損する**ため記載する。

固定フレーズ54語への部分文字列一致で「煽り文面」を判定していたが、実測の結果:

- 言い換え3パターンすべてを見逃す
- 英語・中国語を素通しする
- **正規の銀行の本物の注意喚起に反応する**（「不正なアクセスを検知したため、ご本人様確認の…」）

オオカミ少年化して警告全体が無視される方が危険なため、該当の信号を撤去した。
サポート詐欺の検出は、文面ではなく**構造**（電話への誘導・離脱妨害・名乗っているブランド）に組み替えた。
文面判定が必要な場合は、`services.classifyText` を注入して model 段の検出器に担当させる設計にしてある。

## 4. 検証して問題がなかった項目

| 観点 | ASVS | 結果 |
|---|---|---|
| 動的コード実行（`eval` / `new Function` / `innerHTML`） | V5.2.4 | **0件**。DOM生成はすべて `createElement` + `textContent` |
| リモートコードの読み込み | V14.2 | **なし**。全スクリプトを同梱。外部CDN参照なし |
| `web_accessible_resources` | V14.4 | **未宣言**。Webページから拡張ページを読み込めない |
| `externally_connectable` | V13.2 | **未宣言**。他サイト・他拡張からメッセージを受け取らない |
| 権限の最小化 | V1.2 | `tabs` 権限を使わず `host_permissions` で代替。5権限のみ |
| 秘密情報の保存 | V6.4, V8.2 | APIキー等を保存しない（下記の受容リスク参照） |
| 正規表現のDoS耐性 | V5.2 | 入れ子量指定子なし。入力長は上限付き（本文1500文字、フィールド40件） |
| 外部障害時の挙動 | V7.4.1 | 検出器1つの失敗で判定全体を止めない（`onError` で継続） |

## 5. 受容したリスクと制約

| 項目 | 内容 | 判断 |
|---|---|---|
| 広い `host_permissions` | `http://*/*` `https://*/*` を要求 | webNavigationイベントの受信に必須。機能上避けられない |
| 許可リストの同期 | `storage.sync` 経由でGoogleアカウントに同期される | 利用者が許可したドメイン名のみ。閲覧履歴そのものではない。READMEに明記 |
| APIキーを保存しない | `sanitizeSettingsPatch` が `apiKey` を破棄する | `storage.sync` に置くとGoogleへ同期されるため。キーが必要な場合はエンドポイントURLに含める運用（設定画面上は可視）|
| 検出の回避可能性 | 悪意あるページはDOMを偽装して層4を欺ける | 原理的に不可避。層1（リスト）と層2（URL構造）は影響を受けない |
| 同梱リストが空 | `extension/data/blocklist.json` は0件 | フィードの再配布可否は利用者側の判断。取り込み手順はREADMEに記載 |

## 6. 対象外

- Chrome本体・V8・Chromiumの脆弱性
- 利用者が設定した外部サービス側のセキュリティ
- サプライチェーン（npm依存はPlaywrightのみ、拡張本体は依存ゼロ）
- 物理アクセス・マルウェア感染済み端末

## 7. 再現方法

```bash
npm run test:unit    # tests/unit/security.test.mjs に ASVS 章番号付きで収録
npm run test:e2e     # tests/e2e/privacy.spec.mjs に通信・信頼境界の検証
```
